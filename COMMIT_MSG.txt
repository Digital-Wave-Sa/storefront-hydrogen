Close identity, wallet and branch-data defects ahead of release

Identity and access
- Login could resolve to the wrong customer. Shopify's customer search is
  fuzzy, and a bare-digit query plus an endsWith filter meant a shopper could
  be signed in as somebody else — orders then landed on that account. Every
  lookup now requires exact phone equality and never falls back to another
  customer. The same loose matching was removed from order-stats, loyalty,
  wallet, feedback-analytics, register and the product route.
- Custom cake draft orders were always attributed to one customer. The route
  took the first row of a fuzzy Admin search with no verification, and that
  search took priority over the known session id. The session id now wins, and
  a searched result must match the signed-in shopper or the draft order is
  created with no customer rather than the wrong one.
- Registration accepted any OTP. A failed verifyOtp was caught, logged as
  "Bypass Mode Active" and the flow continued to account creation. Step 4 then
  requested a Shopify access token with the submitted email and a password
  derived from the phone number, which matches for every account made through
  this flow — so submitting an existing customer's phone and email returned a
  real session for them. Verification failure now stops registration.
- Password recovery returned "No customer found with email <address>", turning
  the form into a membership oracle. All outcomes now answer identically; the
  reason goes to the server log without the address.
- A failed OTP send still advanced to the code screen on both login and
  register. Both now return an error, leave the cooldown unset so the shopper
  can retry, and log what actually happened.

Wallet and loyalty
- The wallet showed two different balances for the same customer — the header
  read a phone-keyed service, the wallet card read a customer-id-keyed one.
  Both now read the customer-id service, and a disagreement is logged rather
  than silently picked between. A phone is not a reliable key.
- The by-phone gift-card lookup percent-encoded a leading +, and a URL path is
  not decoded before route matching, so it answered 400 for every customer
  whose Shopify phone is stored in + form.
- Store credit moved server-side: new /api/store-credit resolves the customer
  from the session, so the browser no longer sends a Shopify customer gid with
  no credential attached. StoreCreditBalance and GiftCardActivation call it.
- An unknown store-credit balance rendered as 0.00 while the account header
  correctly said unavailable. It now says unavailable in both places.
- getLoyaltyFullInfo returned {balance: 0} on outage, timeout or stale cache,
  which passed every downstream "is this known" check and produced
  "0 points, SILVER tier" from a failed request. It now returns null.
- The store-credit host reads STORE_CREDIT_API_URL in all four call sites
  instead of one, and the variable is declared in the Env type.

Branch data
- root.tsx, CartSummary and the branches page queried delivery_hours_from/to,
  which exists on no location; every branch stores delivery_time_from/to.
  Three places that silently read nothing now see the real delivery window.

Order status
- The order history normalised tags to underscores while the tracking page
  normalises to hyphens, so hyphenated ERP tags matched on one screen and were
  invisible to the other. Both now use the same normalisation, and the order
  history's lookup keys are hyphenated to match. Underscore and space spellings
  still fold in.

Storefront correctness
- Add to Cart offered stock the selected branch does not hold: before the
  inventory request resolved the card fell back to the global availability
  flag. The button now waits only where the fallback would be guessing, and a
  failed batch retries then parks instead of leaving the card wrong.
- Two certain ReferenceErrors: numericProductId was out of scope in the
  metafield step of the stock-notification route, and export.tsx read an
  undefined `q` left behind by a rename.
- account.tsx's walletPromise type named two fields and typed both as plain
  numbers after the balance became nullable.

Cart, catalogue and promotions
- Gift cards were treated as physical products in the cart: offered gift
  wrapping, and marked out of stock at branches that do not stock a voucher.
  Voucher lines are now identified by product identity rather than by
  requiresShipping, which is false for ordinary products under branch
  fulfilment.
- The wishlist ignored branch availability. A React Router Outlet context
  replaces its parent's rather than extending it, so the selected branch never
  reached the wishlist route.
- Best Sellers' Gifts tab listed products that are not gifts; it now filters on
  the gift tag. A hooks-order crash in the same file removed two homepage
  sections entirely.
- Promotions rebuilt around a promotion_offer metaobject registry, so offers
  can be added, reordered and retired in Shopify without a deploy. Offer pages
  now list only that offer's products, with before and after prices.
- The account dashboard was rebuilt to match the orders list, and product
  names on it are Arabic again — the orders query runs @inContext but did not
  select the localised title.
- Mobile: the navigation drawer would not scroll, order cards named products
  differently from desktop, and the cake-builder FAQ box was oversized.
- The mock gift-card routes are gated to development, so they 404 in a
  production build.

Typography
- Gotham was declared but never shipped: no files in the repo, and the
  @font-face led with local(), so it rendered on machines that had it
  installed and fell to Segoe UI, Helvetica or Roboto for everyone else.
  Replaced with Montserrat across nine sites. Two fallback bugs went with it —
  an English heading resolving to Cairo, and three voucher strings dropping to
  bare sans-serif.

Housekeeping
- Removed both dead copies of translateOtpErrorMessage (~220 lines), which
  described a country restriction the app does not have.
- .env.example completed: nine undocumented variables including the GRAPH_*
  and RESEND keys that email depends on under Oxygen, where SMTP cannot work.
- env.d.ts: five declarations added.
- Added client and developer documentation under guides/: product tags,
  product metafields, branch settings, metaobjects, order status tags, and a
  developer reference of configuration mismatches.
- README rewritten — it still described Remix and Node 18.

Known and not addressed here
- crm-orders.server.ts fabricates success on 401/403 and network errors,
  including invented order numbers and loyalty balances, with no NODE_ENV
  guard.
- Two API keys are hardcoded in source and need rotating.
- None of these changes has been exercised at runtime.
